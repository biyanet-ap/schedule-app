# 스케줄관리 (개인 일정·작업기록 앱)

Google Apps Script 웹앱 + Google 스프레드시트로 돌아가는 **개인용** 일정·작업기록 앱입니다.
서버·DB·도메인이 따로 필요 없고, **각자 자기 Google 계정에 설치해서 혼자 씁니다.**

## 이런 식으로 동작합니다
| 항목 | 내용 |
|---|---|
| 설치 위치 | 설치하는 사람의 Google 계정 (Apps Script 프로젝트 1개 + 스프레드시트 1개) |
| 데이터 | 본인 Google 드라이브의 `스케줄관리 DB` 스프레드시트. 다른 사람과 공유되지 않습니다 |
| 접속 | 본인 계정으로 로그인해야만 열립니다 (웹앱 액세스 "나만" + 서버에서 소유자 재확인) |
| 알림 메일 | 본인 Gmail에서 본인에게 발송 |
| 코드를 준 사람 | 설치된 앱·데이터·메일 어디에도 관여하지 않고, 볼 수도 없습니다 |

## 주요 기능
| 기능 | 내용 |
|---|---|
| 월 캘린더 | 작업·회의 일정, 작업기록, 구글 캘린더 회의(읽기 전용), 일본 공휴일을 한 화면에 표시. 토·일·공휴일은 빨간 날짜 |
| 일정 관리 | 작업/회의, 종일·시각, 우선순위, 프로젝트, 태그, 장소·회의 링크, 상태(예정/완료/취소) |
| 작업기록 | **하루 기록**(날짜별 여러 건)과 **기간 기록**(시작일~종료일, 최대 92일, 이번 주·지난 주·이번 달 빠른 선택). 타이틀·내용, 프로젝트, 태그, 연결 일정, **상태(진행 중/완료)** — 날짜 패널의 "✓ 완료" 버튼으로 바로 완료 처리 |
| 다이어리 | 날짜별 한 편(타이틀·내용, 타이틀을 비우면 날짜로 저장). 헤더의 `📔 다이어리`에서 월~일 주 단위로 보기, 다이어리 검색 |
| 검색 | 작업기록·일정 키워드 검색(태그 포함), 프로젝트 필터, **기간 필터**(이번 달·지난 달·최근 3개월·올해·직접 지정) |
| 주간 보고 | 헤더의 `📋 주간 보고`: 한 주(월~금)의 완료·진행 중 작업, 미완료 일정, 다음 주 예정을 프로젝트별로 묶은 글을 만들어 고친 뒤 복사 |
| 삭제 복구 | 일정·작업기록·다이어리를 지우면 알림의 `되돌리기`로 바로 복구(10초). 나중에는 헤더의 `🗑` 휴지통에서 최근 30일 안에 지운 것을 골라 복구 |
| 아침 알림 | 앱 접속 시 "오늘 요약" 팝업(하루 한 번) + 평일 07~08시 요약 메일 (주말·일본 공휴일 제외, 시각은 설정에서 05~10시 중 선택). 오늘 일정·회의·기한 지난 작업·**진행 중인 작업**(팝업에서 바로 `✓ 완료`) |
| 백업 | 매주 월요일 새벽 스프레드시트를 드라이브 백업 폴더에 복사, 최근 8개 보관 |
| 로고·탭 아이콘 | 머리글에 앱 로고. 편집기에서 `setupFavicon`을 한 번 실행하면 브라우저 탭 아이콘으로도 씁니다 (선택, 아래 10번) |
| 언어 | **한국어·일본어**. 처음에는 브라우저 언어(둘 다 아니면 일본어), `⚙ 설정` → `일반` → `언어`에서 지정하면 모든 기기에 적용. 아침 메일도 같은 언어 |

**지원 범위:** 일본 시간(UTC+9) 기준입니다. 한국도 UTC+9라 시각은 그대로 맞지만, 공휴일은 일본 공휴일을 씁니다.

## 파일 받기 (GitHub)
이 앱은 GitHub 비공개 저장소 `biyanet-ap/schedule-app`으로 나눠 줍니다.
1. 초대 메일의 **초대 수락(Join)** 을 누릅니다 (GitHub 계정이 필요합니다)
2. GitHub에 로그인한 상태로 **https://github.com/biyanet-ap/schedule-app/releases** 를 열고, 최신 버전의 **`schedule-app.zip`** 을 받아 압축을 풉니다 (「Source code」가 아니라 `schedule-app.zip`)
3. 아래 **설치 방법 A**를 따라 합니다. 개발자는 `git clone https://github.com/biyanet-ap/schedule-app.git` 후 **설치 방법 B**
- 새 버전 알림을 받으려면 저장소 오른쪽 위 **Watch → Custom → Releases** 를 체크합니다
- 업데이트는 새 `schedule-app.zip`을 받아 아래 「업데이트 받았을 때」대로 합니다. 릴리스 설명에 `setup` 실행이나 권한 재승인이 필요한지 적혀 있습니다

## 설치 방법 A: 브라우저만으로 설치 (권장, 약 15분)
프로그램 설치 없이 크롬만 있으면 됩니다. 받은 폴더의 **`apps-script/`** 안에 있는 파일 3개를 씁니다.

| 파일 | 넣을 곳 |
|---|---|
| `apps-script/Code.gs` | 편집기의 `Code.gs` |
| `apps-script/index.html` | 새로 만드는 HTML 파일 `index` |
| `apps-script/appsscript.json` | 편집기의 `appsscript.json` |

1. 크롬에서 앱을 쓸 Google 계정으로 로그인한 뒤 **https://script.new** 을 엽니다 → 새 Apps Script 프로젝트가 만들어집니다
2. 왼쪽 위 "제목 없는 프로젝트"를 눌러 이름을 **`스케줄관리`** 로 바꿉니다
3. 왼쪽 **⚙ 프로젝트 설정** → **"편집기에서 'appsscript.json' 매니페스트 파일 표시"** 체크
4. 왼쪽 **< > 편집기**로 돌아와서 파일 3개를 채웁니다 (각 파일을 메모장으로 열어 **Ctrl+A → Ctrl+C**, 편집기에 **Ctrl+A → Ctrl+V**)
   - `appsscript.json` ← `apps-script/appsscript.json` 내용으로 **전부 교체**
   - `Code.gs` ← `apps-script/Code.gs` 내용으로 **전부 교체**
   - 파일 옆 **＋ → HTML** → 이름 **`index`** 입력(`.html`은 자동으로 붙음) → `apps-script/index.html` 내용으로 **전부 교체**
     (약 500KB라 붙여 넣기에 몇 초 걸릴 수 있습니다)
5. **Ctrl+S**로 저장
6. 위쪽 함수 목록에서 **`setup`** 선택 → **실행** → 권한 승인
   - "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → 스케줄관리(으)로 이동**을 누릅니다. 본인이 만든 스크립트라서 나오는 안내이고, 개발자 이메일도 **본인 계정**으로 표시됩니다
   - 실행 로그에 `[OK] 스프레드시트 생성` 등이 나오면 성공입니다 (Google 계정 언어가 한국어가 아니면 로그는 일본어 `[OK] スプレッドシート作成`로 나옵니다)
7. 함수 목록에서 **`runSelfTest`** → **실행** → 모든 줄이 `[OK]`인지 확인합니다 (공휴일 줄만 `[WARN]`이면 아래 8번)
8. (선택) `[WARN] 일본 공휴일 캘린더`가 나오면: 구글 캘린더 → 다른 캘린더 **＋** → 관심 있는 캘린더 찾아보기 → 지역 공휴일 → **日本の祝日** 추가 → `setup` 한 번 더 실행
9. 오른쪽 위 **배포 → 새 배포** → 유형 선택 ⚙ → **웹 앱**
   - 설명: `v1`
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **나만** ← 꼭 확인
   - **배포** → 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 크롬 북마크에 등록
10. (선택) 브라우저 탭 아이콘: 함수 목록에서 **`setupFavicon`** → **실행** → 웹앱을 새로 고쳐 탭에 로고가 보이는지 확인합니다 (안 보이면 아래 「문제가 생기면」)
    - 내 드라이브에 `스케줄관리_favicon.png`(로고 그림 하나)를 만들고 **링크가 있는 사용자 — 뷰어**로 공유합니다. 웹앱·시트·백업은 그대로 비공개입니다
    - 회사 계정에서 외부 공유가 막혀 있으면 로그에 `[WARN]`만 남고 앱은 그대로 동작합니다 (탭은 구글 기본 아이콘)
    - 다른 곳에 올린 이미지를 쓰려면 ⚙ 프로젝트 설정 → **스크립트 속성**에 `FAVICON_URL`(https로 시작하고 `.png`나 `.ico`로 끝나는 주소)을 추가합니다. 이 값이 있으면 먼저 씁니다

> 화면 문구는 Google 화면 언어 설정에 따라 조금 다를 수 있습니다.

### 업데이트 받았을 때 (방법 A)
1. 새로 받은 `apps-script/Code.gs`, `apps-script/index.html`로 편집기의 같은 파일 내용을 **전부 교체** → 저장
2. 업데이트 안내에 "setup 필요"가 있으면 **`setup`** 실행 (기존 데이터는 그대로이고, 여러 번 실행해도 안전합니다)
3. **배포 → 배포 관리 → ✏ 편집 → 버전: 새 버전 → 배포** (URL은 그대로 유지됩니다)

## 설치 방법 B: 개발자용 (Node.js + clasp)
소스를 고치거나 테스트를 돌릴 분용입니다.

**필요한 것:** Node.js 22.12 이상, 앱을 쓸 Google 계정

```powershell
# 0) 이 폴더에서
npm ci

# 1) Apps Script API 켜기 (브라우저)
#    https://script.google.com/home/usersettings → "Google Apps Script API" 사용

# 2) clasp 로그인 (앱을 쓸 계정으로)
npx clasp login

# 3) Apps Script 프로젝트 만들기 → .clasp.json 생성됨
npx clasp create-script --type standalone --title "스케줄관리" --rootDir gas

# 4) 테스트 + 빌드 + 업로드 (매니페스트 포함)
npm run push
```

5. `npx clasp open-script`로 편집기를 열고 **`setup`** → **`runSelfTest`** 실행 (방법 A의 6~8번과 같음). 배포 뒤 탭 아이콘은 방법 A의 10번(`setupFavicon`)
6. 웹앱 배포
   ```powershell
   npx clasp create-deployment --description "v1"
   npx clasp list-deployments   # @HEAD가 아닌 줄의 ID가 배포 ID
   ```
   편집기 `배포 → 배포 관리`에서 **실행: 나 / 액세스 권한: 나만** 인지 확인합니다.

### 업데이트 (방법 B)
```powershell
npm run push
npx clasp create-version "변경 내용"
npx clasp update-deployment <배포ID> --versionNumber <방금 만든 버전>
```
> **시트 열이 추가된 버전**은 `npm run push` 뒤에 편집기에서 **`setup`을 한 번 실행**하세요.

### 롤백
```powershell
npx clasp list-versions
npx clasp update-deployment <배포ID> --versionNumber <이전 버전>
```

### 로컬 개발
```powershell
npm run dev        # 샘플 데이터로 화면 개발 (Google 연결 없음) → http://localhost:5173
npm test           # 서버(gas/*.js)·화면 유틸 테스트
npm run typecheck  # 타입 체크
```

## 설정 바꾸기
앱 헤더의 **⚙ 설정** → `일반` 탭에서 바꾸고 `저장`을 누릅니다 (v1.12, 언어는 v1.13). 같은 창에서 예약 작업 상태 확인·`다시 걸기`, `테스트 메일 보내기`, 최근 발송 기록을 볼 수 있습니다. 프로젝트 관리는 `프로젝트` 탭에 있습니다.

값은 스프레드시트 `스케줄관리 DB`의 `settings` 시트에 저장됩니다. 시트에서 직접 고쳐도 되지만, **발송 시각(`digest_hour`)은 앱에서 바꿔야** 예약이 함께 바뀝니다 (시트만 고쳤다면 설정 창의 `다시 걸기`).

| key | 기본값 | 의미 |
|---|---|---|
| notify_enabled | TRUE | 아침 메일 발송 |
| digest_hour | 7 | 아침 메일 발송 시각 (5~10, 그 시각 ~ 1시간 사이) |
| notify_when_empty | TRUE | 오늘 일정이 없어도 메일 발송 |
| skip_holidays | TRUE | 일본 공휴일에는 메일 안 보냄 |
| today_popup | TRUE | 앱을 그날 처음 열 때 오늘 요약 자동 표시 (모든 기기 공통) |
| backup_keep | 8 | 보관할 백업 개수 (1~100) |
| language | auto | 화면·메일 언어: `auto`(브라우저 언어), `ko`, `ja`. 모든 기기 공통 |

## 문제가 생기면
| 증상 | 확인할 곳 |
|---|---|
| 알림 메일이 안 옴 | 스프레드시트 `notify_log` 시트 (SENT / SKIPPED_WEEKEND / SKIPPED_HOLIDAY / FAILED) |
| 화면에 "초기 설정이 필요합니다" | 편집기에서 `setup` 실행 |
| 화면에 "권한이 없습니다" | 설치한 계정과 다른 계정으로 접속한 경우입니다. 크롬 프로필·계정을 확인하세요 |
| 서버 오류 | 편집기 왼쪽 **실행 기록** |
| 탭 아이콘이 안 보임 | `runSelfTest`의 `파비콘` 줄. `[WARN]`이면 `setupFavicon` 다시 실행. 공유가 막힌 계정이면 `FAVICON_URL`로 다른 곳의 이미지를 지정 |

## 데이터 삭제 (앱을 그만 쓸 때)
1. 편집기 **트리거**(⏰) 메뉴에서 트리거 2개 삭제
2. **배포 관리**에서 웹앱 배포 보관처리
3. 드라이브에서 `스케줄관리 DB`, `스케줄관리_backup` 폴더, `스케줄관리_favicon.png`(만들었다면), `스케줄관리` 스크립트를 삭제

## 폴더 구조
```
apps-script/             브라우저 설치용 파일 3개 (전달 패키지에만 있음)
config/appsscript.json   Apps Script 매니페스트 원본 (권한 범위, 웹앱 설정)
gas/                     서버 코드 (Apps Script)
src/                     화면 (Vue 3)
tests/                   테스트
scripts/                 빌드·전달 패키지 스크립트 (make-icons.mjs: 로고를 바꿀 때 아이콘 다시 만들기, sharp 필요)
assets/                  로고 원본(logo.svg)과 PNG
```
